# 觀眾冷讀協定 · Audience Cold-Read Pass

> 留白要留在人心，不要留在事件。觀眾願意推「為什麼」，不願意猜「發生了什麼」。

## 0. 核心命題

- 編劇腦中有人物表、前史、場次表；觀眾只有銀幕。寫的人覺得「顯然」的地方，最常是觀眾「一頭霧水」的地方。
- Pass 3 把台詞往少裡砍；Pass 4 確認砍完的骨頭還撐得住。兩者方向相反，缺一不可。
- **兩種縫隙**：
  - **人心**（動機、情緒、沒說出口的那句、誰其實想要什麼）→ 准留白，這是詩意的來源。
  - **事件設定**（誰跟誰什麼關係、發生了什麼事、錢或東西去了哪、賭注是什麼、規則是什麼）→ 必須清楚送達。
- 資訊太少，觀眾在猜「發生了什麼」；資訊太多，觀眾在等你講完他早就懂的事。兩種都會讓人滑走。

## 1. 觀看假設與推論上限

**推論步數**＝觀眾從「聽到／看到的」走到「該懂的」，中間要自己補的環節數。
例：「你媽打來，跟我說謝謝。」→ 謝什麼 → 謝那筆錢 → 錢是寄給他媽 → 她原本不知道＝**3 步**。

| 成品長度 | 預設觀看情境 | 單一縫隙推論上限 | 刻意懸念的回收窗 | 每句新增事件上限 |
|---|---|---|---|---|
| ≤ 90 秒 | 手機、只看一次、常靜音看字幕 | 1 步 | 1–2 句內（約 5–10 秒） | 1 件 |
| 3 分鐘 | 手機、只看一次 | 1 步（中點轉折可 2 步，須有基準線） | 30 秒內 | 1–2 件 |
| 5–30 分鐘 | 較專心、不倒帶 | 2 步 | 當場或下一場 | 2 件 |
| 長片 | 專心、資訊可累積 | 可設計多步謎題 | 同一序列內，或以明確伏筆回收 | — |

立項若指定了觀看情境（影展、課堂示範、大銀幕），依該情境放寬或收緊；未指定就用上表。

## 2. 資訊帳本

**Pass 0 起草，Pass 4 對帳。** 列出觀眾「必知」的事——拿掉它，結尾那一拍就失去份量。

```
#｜必知內容｜類型｜預定送達（場次・第幾句／拍）｜通道｜推論步數
1｜他兩年來每月偷寄一萬給媽媽｜事件｜S01 第 3 句｜台詞＋存簿｜1
2｜他們在存生小孩的錢｜事件｜S02 第 2 句｜台詞｜0
3｜她其實不想生｜人心｜S02 末句（反推）｜台詞｜1
```

- 通常 3–6 件。≤ 90 秒的片超過 5 件＝故事對這個長度太重，回 Pass 0 砍一條線。
- **類型只有兩種**：「事件」必須清楚送達；只有「人心」准留白。
- brief 裡使用者明講的設定（年數、關係、地點、觸發事件）一律列為必知；刻意不交代的，在【修訂紀錄】揭露。

## 3. 冷讀三規則

1. **只准用銀幕**：畫面、聲音、字幕。人物表、前史、場次表、Logline 一律當作不存在——職業寫在人物表卻沒上銀幕，就等於沒有。
2. **播放速度**：每句只有它說出口的那幾秒，不准倒帶。≤ 3 分鐘預設靜音看字幕，只靠音效送達的資訊打五折。
3. **逐拍寫內心旁白**，每拍一行，只准四種標記：

| 標記 | 意思 | 判定 |
|---|---|---|
| 我知道… | 資訊已送達 | ✓ |
| 我在猜… | 懸念 | 回收窗內有答案或加深 ✓；否則 ✗（霧） |
| 我搞不懂… | 壞縫隙 | ✗ |
| 我早就知道了 | 過量 | ✗（刻意的重複與變奏除外） |

## 4. 九項審查

| # | 檢查 | 失敗徵兆 | 典型解法 |
|---|---|---|---|
| 1 | 推論步數 | 超過 §1 的上限 | 補名詞、轉成引述 |
| 2 | 縫隙位置 | 觀眾在猜事件，而不是在推人心 | 把事件講清楚，留白挪到人心 |
| 3 | 錨點 | 「那一半」「那筆」「一百萬」這類代稱，觀眾之前從沒聽過它指的名詞 | 第一次出現時帶上名詞 |
| 4 | 通道可靠度 | 必知資訊只放在：畫面上的字（文件、手機螢幕、招牌——AI 影片多半糊掉）、要心算的數字、只有音效、只有細微表情、非通用的在地符碼 | 移到台詞或大動作；在地符碼只當加分 |
| 5 | 轉折基準線 | 翻轉前，觀眾還沒確實相信被翻掉的那件事——轉折讀起來像混亂，不像意外 | 先讓基準句站穩，再翻 |
| 6 | 回收窗 | 刻意懸念過了回收窗，既沒有答案也沒有加深 | 提前回收，或加一拍把它加深 |
| 7 | 過量 | 「我早就知道了」；一句塞兩件以上新事件；轉折被提早洩漏；台詞講畫面已演出的事 | 刪 → 延後 → 拆成兩拍 → 改成動作 |
| 8 | 設定保留 | brief 明講的設定，銀幕上接收不到 | 用一個詞塞進既有台詞（例：「七年，」） |
| 9 | 結尾可讀 | 觀眾說不出最後一拍「發生了什麼」 | 換成不用讀字、不用計算的動作或聲音 |

**結尾的分寸**：意義可以開放，事件不行。「不知道他們之後會怎樣」＝開放結局 ✓；「不知道剛剛發生什麼」＝沒寫清楚 ✗。

## 5. 最小侵入修補順序

依序套用，第一個成立的就用：

1. **補一個名詞**到既有台詞（「你那一半」→「小孩的錢，你那一半」）。
2. **換通道**：畫面上的字、數字，改由台詞說出或改成大動作。
3. **轉成引述**：讓角色轉述第三者的話——資訊變成證據，不是說明（「你媽打來，謝謝我每個月寄一萬給她」）。
4. **重排**：錨點移到代稱之前、基準句移到轉折之前。
5. **改收尾**：不可讀的最後一拍，換成可讀的動作或聲音。
6. **最後才加**一句台詞或一個畫面——先查 `format-and-output.md` 的台詞量上限；非加不可，代表資訊順序壞了（回 Pass 1）。

**護欄**
- 補進去的資訊必須是**武器、證據或請求**——是這個角色此刻真的會對對方說的話。純說明（As you know, Bob）不准。
- 修過的句子，重跑 Pass 3 的四個測試與七大禁區。
- 修的是錨點與通道，不是加話：修完的台詞總量應與修前相同或更少。

## 6. 回述測試與退出條件

- **回述測試**：冷讀結束，用觀眾的口吻一句話說出「剛剛發生了什麼」。回述必須包含 Logline 裡的每一個事件要素；缺哪個，就回帳本補哪個。
- **退出條件**：帳本全部送達、沒有任何「我搞不懂」、「我早就知道了」只出現在刻意的重複與變奏。
- **回退**：補洞非加台詞不可 → 資訊順序或場次功能壞了（回 Pass 1）；必知清單在長度內塞不下 → 故事對這個長度太重（回 Pass 0）。

## 7. 案例：〈第七年〉60 秒

夫妻在客廳為錢吵架；台詞 8 句，修前修後句數不變。

| 冷讀旁白 | 修前 | 問題 | 修後 |
|---|---|---|---|
| 「謝什麼？」 | 你媽打來，跟我說謝謝。 | 推論 3 步 | 你媽打來，謝謝我每個月寄一萬給她。 |
| 「哪個一半？」 | 你說你那一半，還生不起。 | 沒有錨點 | 你說小孩的錢，你那一半還存不夠。 |
| （從沒出現） | brief 寫「結婚第七年」 | 設定遺失 | 七年，家用我那一半，一塊都沒少過。 |
| 「他轉錢給她？為什麼？」 | 結尾手機跳出「入帳 921 元」 | 靠畫面文字＋心算 | 他拎垃圾桶進廚房，水一直沒關；她拿計算機算電費 |
| 「她其實不想生？」 | 存到了，你會改成兩百。 | ✓ 人心縫隙，1 步 | 保留（只把「改成」換成「改口說」） |
