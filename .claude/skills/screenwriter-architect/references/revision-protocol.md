# 內部多稿淬鍊協定 · Internal Revision Protocol

> 使用者看到的「第一版草稿」，至少是內部的第五版。
> 本協定全程在思考內部執行：**不輸出任何一稿的過程、不展示審查表、不說「我先寫了一版然後改」。**

## 0. 鐵則

1. **最少四輪改寫**（α → β → γ → δ → ε）。一稿出貨＝這個 skill 沒有被使用。
2. **每一 Pass 只做一件事**。混著改會兩件都做不好。
3. **每一 Pass 必須真的動刀**。「檢查後認為沒問題」若連續出現兩次，才可收斂；第一輪就宣稱完美＝沒認真審。
4. **回退合法**：Pass 3 發現台詞救不了，通常是 Pass 1 的場次設計壞了 → 退回重排，不要在台詞層硬撐。
5. **過程不外洩**：輸出只有 Draft ε（或更後面的稿）與【修訂紀錄】。
6. **大綱也要跑完**：交付形式是純故事大綱或分場大綱時，照樣走完全部 Pass——Pass 1 與 Pass 4 審大綱裡的每個轉折，Pass 2–3 只處理大綱裡出現的台詞。字數限制在 Pass 5 之後才動刀；刪完重跑 Pass 1 的讓步換手與 Pass 4 的回述測試——刪字最容易刪掉因果。

---

## Pass 0 · 骨架推演

依 `craft-structure.md` 鎖死：

- Logline（一句話公式）
- Want vs Need（必須互相拉扯）
- 主題論證（「〔X〕必須以〔Y〕為代價」）
- 結局與情緒落點；**最壞結果可不可挽回**，要與立項的調性一致（`craft-structure.md` §3）
- **核心情境**（選用）：只有使用者明講要某一類情境時（例：「寫一個復仇故事」）才選卡——依 `situation-design.md` 替高潮場套用那張卡，把必要角色換成故事裡的人。其他情況一律不選卡：brief 已經寫出衝突的，照它寫；只有主題的，自己找出「誰想要什麼、被誰擋住」。
- 依 `format-and-output.md` 的換算表決定 **場次數／頁數／台詞量**
- 產出 **場次表**：`編號｜場景｜核心問題（主要對方）｜主要轉換｜結果與價值轉向(＋/－)`（`craft-structure.md` §8）
- 依 `audience-pass.md` §2 起草 **資訊帳本**：觀眾必知的 3–6 件事、類型（事件／人心）、預定在哪一拍、經由什麼通道送達；brief 明講的設定全部列入。

**卡關處理**：三件事鎖不死就不要往下寫。缺的用立項預設值補，並記下來要寫進【立項確認】。

## Draft α · 快而醜

把場次表寫成完整劇本。**不修飾、不斟酌用字、允許台詞很爛**。目的只是讓整個故事以可審查的形態存在。

在這一稿允許：直白的台詞、暫時的佔位描述、過長的場次。

---

## Pass 1 · 結構審查 → Draft β

逐場提問（全部都要問）：

- 刪掉這場，後面會不會壞？不會 → **刪**。
- 情緒／權力值有沒有翻轉？沒有 → **加阻礙或合併**。權力的翻轉只是語氣強弱、沒有籌碼換手 → **讓一個把柄、證據或承諾換手**。
- 這場演在主角和「答案取決於他」的人之間嗎？不是 → **把對質移到握有答案的人面前**。
- 主角為誰而戰？那個人在銀幕上感受得到嗎？感受不到 → **讓他在場，或給一件東西、一句話**。
- 最壞結果可不可挽回，與調性一致嗎？不一致 → **調賭注，不是調台詞語氣**。
- 事件、道具、笑點的誇張程度符合立項調性嗎？寫實調性裡出現「旁人會說這也太怪」的事 → **換成日常版本**，不准靠奇觀製造笑點或記憶點（`craft-structure.md` §3）。
- 有人讓步、放行、相信或說出秘密嗎？說得出換手的是哪個新事實或籌碼、為什麼對這個人有效嗎？說不出來，或讓步前後他聽到的其實是同一件事 → **重設對方的反對理由**，不准用笑點或氣氛補洞（`craft-structure.md` §2）。
- 這場承擔幾個功能？超過一個 → **拆或減**。
- 與前一場能不能用「因此／但是」串起？只能用「然後」 → **重排或補因果**。
- 進點會不會太早？出點會不會太晚？→ **晚進早出**。
- ＋／－標記有沒有連續三場同向？主要轉換有沒有連續三場同一種？→ **重排**。
- 主角這一幕有沒有至少一次「自己決定去做某事」？沒有 → **改成主動**（主動不等於能控制結果，見 `craft-structure.md` §4）。
- 某場有翻轉卻還是沒力 → 讀 `situation-design.md`，**找出平掉的旋鈕，或對照最像那張卡的必要角色與失效條件**。

輸出 Draft β。通常會少 1–3 場。

---

## Pass 2 · 聲口審查 → Draft γ

- **遮名測試**：蓋住角色名讀全部對白，認得出誰在講嗎？認不出 → 分化句長、詞彙深度、直接度、慣用句式。
- 每個角色給一條**語言特徵**（例：只用短句／愛用反問／講話一定先「欸」／講台語時才說真話）。
- **配角功能盤點**：質疑者／鏡像／催化劑／代價體現者。無功能 → 合併或刪除。
- **反派辯詞**：能不能替對抗方寫出一段他自己相信的說法？不能 → 他還太扁。
- 檢查角色之間的資訊經濟：誰在什麼時候知道什麼，是刻意安排的嗎？（觀眾端的資訊送達留給 Pass 4。）

輸出 Draft γ。

---

## Pass 3 · 台詞淬鍊 → Draft δ

依 `craft-dialogue.md` **逐句**處理：

1. 跑四測試（朗讀／遮名／明信片／刪除）。
2. 對每一句失敗的台詞跑「快速改寫刀法」七步，第一個成立的就用。
3. 掃描七大禁區，命中即重寫。
4. 掃描抽象警訊詞（命運／孤獨／永遠／靈魂／救贖／世界／溫暖）→ 換成具體物件——挑日常常見的那一件，不挑最奇特的（`craft-structure.md` §5）。
5. 確認至少有一組**重複與變奏**已埋下並回收。
6. 確認情緒最高的那場，台詞是全劇最短的。
7. 同步清理動作行：任何「難過地／開心地／緊張地」→ 改成可拍的動作。

輸出 Draft δ。

---

## Pass 4 · 觀眾冷讀 → Draft ε

依 `audience-pass.md` 執行。Pass 3 把台詞往少裡砍，這一輪確認砍完的骨頭還撐得住：

1. **冷讀**：以第一次觀看、播放速度、只知道銀幕內容的觀眾身分，逐拍寫內心旁白（我知道／我在猜／我搞不懂／我早就知道了／我不信）。「我不信」＝看得懂發生什麼，卻不信它為什麼發生 → 回 Pass 1 重設原因，不在這一輪加台詞解釋。
2. **對帳**：旁白對照資訊帳本——每件必知資訊有沒有在預定拍點送達、推論步數是否在長度上限內、通道是否可靠。
3. **九項審查**：推論步數、縫隙位置、錨點、通道可靠度、轉折基準線、回收窗、過量、設定保留、結尾可讀。
4. **修補**：依最小侵入順序（補名詞 → 換通道 → 轉引述 → 重排 → 改收尾 → 最後才加句）；修過的句子重跑 Pass 3 的四測試與七大禁區。
5. **回述測試**：用觀眾口吻一句話說出「剛剛發生了什麼」，必須涵蓋 Logline 的每個事件要素。

輸出 Draft ε。

## Pass 5 · 終檢核表

全部通過才可輸出；任一失敗 → 回到括號中的 Pass。

- [ ] 能用一句話講完，且對方聽完想看？（Pass 0）
- [ ] 主角主動採取行動，不是被推著走？（Pass 1）
- [ ] 隨機抽三場，刪掉會影響後面？（Pass 1）
- [ ] 每場的情緒／權力有翻轉？（Pass 1）
- [ ] 每場都演在主角和握有答案的人之間？（Pass 1）
- [ ] 每個讓步、放行或相信，都說得出換手的新事實或籌碼，且對這個人有效？（Pass 1）
- [ ] 遮住名字認得出誰在說話？（Pass 2）
- [ ] 沒有任何台詞在講畫面已經演出來的事？（Pass 3）
- [ ] 第三幕的解法在第一幕埋過伏筆？（Pass 0／Pass 1）
- [ ] 結局回答了開場提出的戲劇性問題？（Pass 0）
- [ ] 最壞結果的可逆性與調性一致？（Pass 0／Pass 1）
- [ ] 事件、道具與笑點的誇張程度符合立項調性？（Pass 1）
- [ ] 用了主卡的話：必要角色都在戲裡，沒有踩到失效條件？（Pass 0／Pass 1）
- [ ] 說得出這部片的主題論證，而且沒有任何角色把它講出來？（Pass 0／Pass 3）
- [ ] 冷讀一次，觀眾能一句話說出發生了什麼，且涵蓋 Logline 的每個事件要素？（Pass 4）
- [ ] 留白全在人心；沒有任何事件要觀眾用猜的，每個縫隙都在推論上限內？（Pass 4）
- [ ] 沒有必知資訊只靠畫面文字、心算、音效或人物表送達？（Pass 4）
- [ ] brief 明講的設定，觀眾都接收得到（或已在【修訂紀錄】揭露刻意省略）？（Pass 4）
- [ ] 場次數、角色數、場景數符合立項規格與預算限制？（Pass 0）
- [ ] 沒有寫鏡頭指示（除非鏡頭本身是敘事手段）？（Pass 3）
- [ ] 卡名、旋鈕名、轉換名，以及「最壞結果可挽回」這類分析語，沒有出現在任何輸出區塊（含【立項假設】）？（輸出前）

## 收斂條件與回退路徑

- **收斂**：連續兩輪 Pass 5 沒有產生新的修改項 → 停止，輸出。
- **下限**：無論如何至少走完 α→β→γ→δ→ε。
- **回退**：
  - 台詞怎麼改都假 → 場次設計有問題（回 Pass 1）。
  - 場次刪不掉也不好看 → 主角目標不夠具體（回 Pass 0 的 Want）。
  - 結局收不起來 → 主題論證沒鎖死（回 Pass 0）。
  - 冷讀的洞非加台詞補不起來 → 資訊順序或場次功能有問題（回 Pass 1）。
  - 必知清單在這個長度裡塞不下 → 故事對這個長度太重（回 Pass 0 砍一條線）。
  - 場次有翻轉卻沒力 → 有旋鈕是平的、必要角色缺席，或踩到失效條件（回 Pass 1，對照 `situation-design.md`）。
  - 調性怎麼寫都不對 → 賭注的可逆性錯了（回 Pass 0）。
  - 某個梗或道具讓寫實調性出戲 → 寫實刻度跑掉了，換成日常版本（回 Pass 1）。
  - 冷讀出現「我不信」→ 讓步缺換手，對方的反對理由要重設（回 Pass 1）；不准用笑點或加一句解釋撐過去。

## 修訂紀錄怎麼寫

輸出末尾的【修訂紀錄】**上限四行**，是證據不是流水帳。每行一句，格式：

```
・結構：原本 9 場壓到 6 場，刪掉〔某場〕因為刪了不影響後續。
・台詞：〔某角〕的告白從直述改為繞路的日常對話，情緒交給觀眾補完。
・觀眾：冷讀時〔某句〕要推三步，補上〔某名詞〕當錨點；〔某資訊〕從畫面文字改由台詞送達。
・假設：未指定〔某項〕，採〔預設值〕。
```

禁止在此區塊出現 Draft α/β/γ/δ/ε 字樣、審查表、冷讀旁白、資訊帳本、卡名或旋鈕名這類內部術語，或「我反覆修改了很多次」這類自我表揚。用故事裡的人和事說明改了什麼。每一行都要指得出改了哪一句、補上的是原因還是只有結果；沒修好的東西不准寫成修好了。
